# 🛒 ระบบบริหารจัดการจัดซื้อจัดจ้าง (GPAMS - Procurement Module)

เอกสารฉบับนี้ระบุข้อกำหนดสำหรับส่วนเพิ่มเติม "ระบบจัดซื้อจัดจ้างและแจ้งซ่อม" โดยเน้นการสร้างเอกสารอัตโนมัติ (Document Automation) ผ่าน Word Template และ Workflow การอนุมัติ 3 รูปแบบ

---

## 🎨 1. UI/UX Extension (TailwindCSS)

ยังคงยึดตาม **Corporate Professional Theme** (Blue-900 / Yellow-600)

### 1.1 Input Forms & Search

- **Asset Search Box:** ช่องค้นหาครุภัณฑ์แบบ Autocomplete
  - Style: `border-gray-300 focus:border-blue-900 focus:ring-yellow-600`
  - Behavior: พิมพ์รหัสหรือชื่อครุภัณฑ์ -> แสดง Dropdown -> เลือกแล้วดึงข้อมูล (ชื่อ, รหัส, ราคากลางเดิม) มาใส่ในฟอร์มอัตโนมัติ
- **Status Badge:**
  - **ขอซ่อม:** `bg-orange-100 text-orange-800 border-orange-200`
  - **ซื้อ (เครดิต):** `bg-blue-100 text-blue-800 border-blue-200`
  - **ซื้อ (เงินสด):** `bg-green-100 text-green-800 border-green-200`

## ⚙️ 2. Functional Workflows (รูปแบบการดำเนินงาน)

ระบบแบ่งการทำงานเป็น 3 ประเภท ตามรูปแบบเอกสารและการเงิน

### 2.1 🛠️ ระบบขอซ่อม (Request for Repair)

- **Access:** เจ้าหน้าที่พัสดุ, ผู้ดูแลระบบ (สามารถสร้างรายการแทน User หรือ User แจ้งเข้ามาแล้วเจ้าหน้าที่กดรับเรื่อง)
- **Process:**
  1.  **Search Asset:** ค้นหาครุภัณฑ์ที่ชำรุดจากฐานข้อมูล
  2.  **Fill Details:** ระบุอาการเสีย, สาเหตุ, วงเงินประเมิน
  3.  **Generate Doc 1:** สร้าง "บันทึกขออนุมัติจ้างซ่อม" (Word)
  4.  **Process:** ดำเนินการจ้าง -> บันทึกผลการตรวจรับ
  5.  **Generate Doc 2:** สร้าง "บันทึกรายงานผลและขออนุมัติเบิกจ่าย" (Word)

### 2.2 🧾 ระบบขอซื้อ - เครดิต (Credit Purchase)

- **Concept:** ออกใบสั่งซื้อก่อน (PO) -> รอของ/รอเงิน -> จ่ายเงินทีหลัง
- **Process:**
  1.  **Form:** กรอกรายการวัสดุ/ครุภัณฑ์ที่ต้องการ (สามารถเลือก Vendor ได้)
  2.  **Generate Doc 1:** สร้าง "รายงานขออนุมัติจัดซื้อ"
  3.  **Wait for Approval:** สถานะเป็น "รออนุมัติงบ/รอของ"
  4.  **Confirm:** เมื่อได้รับของ -> เจ้าหน้าที่พัสดุกดยืนยันการตรวจรับ -> ยืนยันผล (Success)
  5.  **Generate Doc 2:** สร้าง "รายงานผลการตรวจรับและขอเบิกจ่าย"

### 2.3 💵 ระบบขอซื้อ - เงินสด (Cash Purchase)

- **Concept:** ขอยืมเงินทดรอง/เงินสด -> ไปซื้อ -> นำบิลมาเคลียร์
- **Process:**
  1.  **Form:** กรอกรายการ (วงเงินต่ำ)
  2.  **Generate Doc 1:** สร้าง "รายงานขออนุมัติจัดซื้อ (เงินสด)"
  3.  **Withdraw:** สถานะ "รอเบิกเงินสด" -> เจ้าหน้าที่การเงินยืนยันการจ่ายเงิน
  4.  **Clearance:** นำใบเสร็จเข้าระบบ -> ยืนยันผลการเคลียร์เงิน
  5.  **Generate Doc 2:** สร้าง "รายงานสรุปผลการจัดซื้อ"

## 📝 3. Word Template Mapping (PHPWord Integration)

การใช้ Template จะใช้รูปแบบ `${variable_name}` ในไฟล์ .docx เพื่อให้ระบบแทนที่ข้อมูลอัตโนมัติ

### 3.1 Template: ขอซ่อม (Repair)

อ้างอิงไฟล์: _ขอซ่อม.docx_
ใช้สำหรับสร้างเอกสาร: **บันทึกขออนุมัติจ้างซ่อมแซม**

| Field ในเอกสาร           | ตัวแปร Template (`${...}`) | ตัวอย่างข้อมูล                     |
| :----------------------- | :------------------------- | :--------------------------------- |
| เลขที่หนังสือ            | `${doc_no}`                | 86/2569                            |
| วันที่                   | `${doc_date}`              | 30 มกราคม 2569                     |
| เรื่อง                   | `${subject}`               | ขออนุมัติจ้างซ่อมแซม...            |
| เรียน (ตำแหน่ง)          | `${to_position}`           | ผู้อำนวยการสำนักอำนวยการ...        |
| หมายเลขครุภัณฑ์          | `${asset_id}`              | 6350-003-0001/2                    |
| สาเหตุ/อาการ             | `${repair_reason}`         | กล้องวงจรปิดไม่สามารถใช้งาน...     |
| รายละเอียดการซ่อม        | `${repair_detail}`         | เปลี่ยนอุปกรณ์ Switch HIKVISION... |
| ราคากลาง/วงเงิน          | `${total_price_thai}`      | เจ็ดพันสี่ร้อยเก้าสิบบาทถ้วน       |
| จำนวนเงิน (ตัวเลข)       | `${total_price_num}`       | 7,490                              |
| กำหนดส่งมอบ (วันที่)     | `${delivery_date}`         | 30 มกราคม 2569                     |
| ชื่อผู้ตรวจรับ (กรรมการ) | `${inspector_name}`        | นายเอกวิทย์ ลาดล้าย                |
| ตำแหน่งผู้ตรวจรับ        | `${inspector_position}`    | นักวิชาการคอมพิวเตอร์ปฏิบัติการ    |
| เจ้าหน้าที่พัสดุ         | `${supply_officer}`        | นางณัฐรินันก์ กุบแก้ว              |
| ผู้อำนวยการ              | `${director_name}`         | นางสาวเนตรดาว เฝ้าทรัพย์           |

## 💻 4. Screen Specifications (หน้าจอการใช้งาน)

### 4.1 Procurement Dashboard (หน้าหลักจัดซื้อจัดจ้าง)

- **Filters:**
  - Dropdown: เลือกปีงบประมาณ
  - Tabs: [ทั้งหมด] [ขอซ่อม] [ซื้อ-เครดิต] [ซื้อ-เงินสด]
- **Table Column:** วันที่, เลขที่, เรื่อง, วงเงิน, สถานะ (Badge), ปุ่ม Action
- **Action Buttons:**
  - **ปุ่ม [พิมพ์บันทึก]:** สีน้ำเงินเข้ม (`bg-blue-900`) -> Download Word (.docx)
  - **ปุ่ม [อัปเดตผล]:** สีเหลืองเข้ม (`bg-yellow-600`) -> เปิด Modal เพื่อกรอกเลขที่ใบตรวจรับ/ใบเสร็จ เพื่อปิดงาน

### 4.2 Form Request Interface (หน้าฟอร์ม)

- **Header:** "บันทึกรายการขอซื้อ/ขอจ้าง" (พื้นหลัง Blue-900 text-white)
- **Section 1: ข้อมูลทั่วไป**
  - เลือกประเภท: Radio Button ขนาดใหญ่ (ซ่อม / ซื้อเครดิต / ซื้อเงินสด)
- **Section 2: รายการพัสดุ (Dynamic Row)**
  - [ค้นหาครุภัณฑ์] [ชื่อรายการ] [จำนวน] [ราคาต่อหน่วย] [รวม] [ปุ่มลบ]
  - _Footer:_ แสดงยอดรวมทั้งสิ้น (Auto Calculate)
- **Section 3: คณะกรรมการ/ผู้เกี่ยวข้อง**
  - ดึงรายชื่อจาก User Database มาใส่ใน Dropdown ให้เลือก "ผู้ตรวจรับ", "เจ้าหน้าที่พัสดุ", "ผู้อำนวยการ"
